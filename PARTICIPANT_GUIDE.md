## 1. Problem statements (build in at least one)

**One: Million Token Engineering.** Argon is SOTA on codebase understanding (long-horizon software engineering). With up to 1M continuous output tokens in one response, it can build systems across hundreds of files, keep interfaces consistent as they change, and grind tedious tasks where other models' accuracy drops. Legacy migrations, language translations, framework upgrades. Pick something that seemed monumental, do it, and **measure your improvement over a baseline**.

**Two: More Dimensions.** Argon is SOTA on long video understanding, and its output window lets it generate high-fidelity 3D games and procedural worlds in a single pass. A single pass is only the first draft. Build a system that **renders what it made, watches the result, critiques it against the goal, and fixes it in a loop**.

## 5. Rules

- **Open source:** repositories must be public.
- **Team size:** 1–4.
- **Demo:** show only features, code and functionality built during the hackathon. Judges must clearly see what was made at the event, or immediate disqualification.
- **New work only:** no existing projects presented as your own.
- **Banned:** anything violating legal, ethical or platform policies, or using code, data or assets you don't have rights to.

### Projects to avoid

AI mental health advisor · basic RAG · Streamlit apps · image analyzers · "AI for Education" chatbot · AI job application screener · AI nutrition coach · personality analyzers · AI medical advice · anything where a dashboard is the main feature · sports analyzers/coaches.

## 7. Submission

Submit on the event page. Required: a **1-minute demo video** of the features, code and functionality built at the hackathon. Repo public, demo link accessible, all team members added to the submission.

## 8. Judging

**Round one:** judging groups in separate rooms. ~3 min live demo + 1–2 min Q&A.

| Criterion | Weight | Question |
| --- | --- | --- |
| Working live demo | **50%** | Runs live with real inputs? Uses `gemini-4-argon`, Managed Agents or companion models effectively, **with a real verification loop**? |
| Problem and usefulness | 25% | Concrete problem for a specific person in one of the tracks? Could it become a product or OSS tool after today? |
| Originality ("never built before") | 15% | Only possible because of Argon's 1M unified context, long decode, frontier reasoning or multimodal orchestration? |
| Clarity of pitch | 10% | Shows who the user is and the working product clearly in 3 min, **no slides**? |

**Round two:** top 6 teams on stage before the panel and all attendees, ~3 min demo + 1–2 min Q&A. Same criteria, **equal weights**.
